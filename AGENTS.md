# AGENTS.md — OfferToday Auto-Apply Bot

## 1. Main goal

Build a personal-use bot for the Hong Kong jobs site **OfferToday** that:
- scrapes **part-time jobs across all categories** (no job-function filter),
- shows a preview for approval,
- for each approved job: applies, clicks **Send resume**, selects the profile CV,
  then sends a configured follow-up chat message,
- uses a **randomized 3–5 second pause only during apply/chat actions** (never while
  scraping),
- runs for a single personal account, with SQLite deduplication to avoid re-applying,
- is usable both as a CLI (`python main.py`) and as a packaged GUI EXE
  (`dist/OfferTodayBot.exe`).

OfferToday's Terms of Service likely prohibit bulk automation; keep the per-run cap
low and use the preview/approval step.

## 2. Files and what they do

### Project root
- `config.yaml` — user settings: search (part-time `[2]`, no categories, 5 pages),
  filters (keywords, salary, locations), `limits.max_applications_per_run`,
  `delays.apply_action: [3.0, 5.0]`, `resume_filename_contains`,
  `follow_up_message`, `assist_on_unknown_dialog`.
- `.env.example` / `.env` — credential template / actual email+password (gitignored).
- `.gitignore` — excludes `.env`, `data/`, `build/`, `dist/`, `*.spec`, `__pycache__`.
- `requirements.txt` — `playwright`, `PyYAML`, `python-dotenv`, `rich`, `pyinstaller`.
- `README.md` — setup, CLI usage, EXE usage, GUI tab guide, notes.
- `main.py` — CLI entry point; also exposes shared `scrape_jobs()` and
  `apply_selection()` used by the GUI.
- `gui_main.py` — EXE entry point; sets `PLAYWRIGHT_BROWSERS_PATH` when frozen,
  hidden `--self-test` diagnostic, launches the Tk app.
- `build.bat` — PyInstaller single-file/windowed build with `--collect-all
  playwright`; copies `config.yaml` and `.env` beside the EXE as first-run seeds.
- `OfferTodayBot.spec` — generated by PyInstaller (gitignored).

### `bot/` package
- `__init__.py` — package marker.
- `runtime.py` — when frozen, resolves ROOT/CONFIG_PATH/DATA_DIR/ENV_PATH to
  `Desktop\OffertodayBOT` (OneDrive-aware); `ensure_defaults()` creates config/.env/
  data and migrates files from beside the EXE on first run.
- `browser_setup.py` — `browsers_installed()` and `install_browser()` which runs the
  bundled Playwright CLI (`node.exe cli.js install chromium`) with no console window;
  used for automatic first-run browser download.
- `utils.py` — `load_config()`, `setup_logging()` (optional queue handler for GUI),
  `human_delay()` (random 3–5s, apply phase only), `parse_salary_min()`.
- `session.py` — Playwright browser lifecycle; login via Email/Phone + password;
  authoritative auth check against `/en/applied-history`; reads `csrf-token` from
  the `Csrf-Token` cookie; `api_post()`; `recover_session()`; prompt callback.
- `scraper.py` — calls `/wapi/geek/recommend/search/list` with `sessionId` threaded
  between pages and `hasMore` pagination; normalizes job cards; optional detail fetch.
- `filters.py` — keyword include/exclude, part-time safety check, salary/location
  filters, scoring; skips only terminal statuses (`applied`, `chatted`, `skipped`)
  so `failed` jobs remain retryable.
- `reviewer.py` — CLI preview table + `data/preview.csv`; accepts `1,3,5`, `(1,2)`,
  `1-5`, `all`, `q` and prints the selection count.
- `storage.py` — SQLite `jobs` table with statuses/timestamps, dedup, `resumed_at`
  migration, `applied_today_count()`, `known_jobs()`.
- `applier.py` — apply → resume → chat pipeline. Resume step: hover **More** (with a
  JS mouseenter fallback for headless mode) → click **Send resume** → handle
  **Select a resume** dialog (choose configured CV, click Send) → skip if "resume
  has been sent" already shown. Chat step: wait for the chat panel after applying;
  find the exact **Send** button (never "Send contact"/"Send resume"), verify
  composer cleared, retry with keystrokes only if needed. Missing steps are logged
  and skipped — no manual prompts. Writes `data/apply_debug.log`.
- `gui.py` — Tkinter app with **Run** (job table with checkboxes, Select all/Clear,
  Scrape/Apply selected/Dry run/Stop, Install browser, live log), **Config** (editable
  settings form), **Account** (credentials + Test login). On startup it auto-downloads
  Chromium if missing and disables bot buttons until ready. Worker threads create
  their own Playwright session; only login/captcha prompts become GUI modals —
  apply/chat steps never prompt.

### Runtime data (gitignored)
- `data/session.json` — saved login state.
- `data/bot.db` — job statuses (prevents duplicate applications).
- `data/preview.csv` — last preview list.
- `data/apply_debug.log` — dialog/button diagnostics for fixing selectors.
- `dist/OfferTodayBot.exe` — packaged app; on first run it creates
  `Desktop\OffertodayBOT` for config/.env/data.

## 3. Current status

### Working (verified)
- Login + session persistence; authenticated API calls with correct CSRF token.
- Scraping 5 pages (~50 results → ~30–35 part-time matches), salary parsing, filters,
  SQLite dedup.
- CLI preview with flexible number input, per-run cap, `--force`.
- Apply flow, resume flow (hover More → Send resume → CV dialog → Send), skip
  already-sent resume, follow-up chat with exact Send button and no duplicate sends.
- Random 3–5s delays only on apply actions; no artificial scraping delay.
- GUI with three tabs, Select all/Clear, threaded actions, log pane.
- EXE builds successfully; self-test (`OfferTodayBot.exe --self-test`) returns OK;
  GUI launches; CLI dry-run works.

### Known limitations / possible bugs
- The full **live apply flow inside the packaged EXE** has not been end-to-end tested
  (only self-test + launch); the CLI flow is what the user has exercised live.
- Playwright Chromium is **not bundled**; the EXE downloads it automatically on
  first launch (needs internet, no Python/admin rights). If offline, use the
  **Install browser** button once connected.
- One-file EXE startup is slow (~5–10s).
- Config/account edits made in the EXE are written to `Desktop\OffertodayBOT`, not
  the project root files.
- ToS/ban risk is inherent; keep the cap low.
